# Fetchalo 插件

[fetchalo](https://github.com/gioboa/fetchalo) 是一个社区插件，它通过你自己的
`fetch` 加载指定 origin 下的 JS、CSS 和媒体资源。这些 origin 的每个请求都可以携带
`Authorization: Bearer …` 等请求头，无需 service worker。

浏览器无法为 `<script type="module">`、`import()`、`<link>`、`<img>` 或 CSS
`url()` 请求添加请求头。service worker 可以做到，但只能在安全上下文（HTTPS 或
`localhost`）中使用，且每个 scope 只能有一个。fetchalo 在普通 HTTP 站点上同样可用，例如部署在局域网内、需要 API key 才能访问的 remote。

在 Module Federation 中，`fetchalo/federation` 运行时插件会通过 fetchalo 加载 remote 的
manifest、`module`/`esm` 类型的 remote 入口、chunk、CSS 和媒体资源。

## 配置

该插件可以在编译时或运行时使用

<Tabs>
  <Tab label="Rspack">
  ```js title="rspack.config.js"
  const {ModuleFederationPlugin} = require('@module-federation/enhanced/rspack');
  const {FetchaloPlugin} = require('fetchalo/rspack');

  module.exports = {
    plugins: [
      new FetchaloPlugin('./src/fetchalo.config.js'),
      new ModuleFederationPlugin({
        // other options
        runtimePlugins: [
          require.resolve('fetchalo/federation')
        ]
      }),
    ],
  };
  ```
  </Tab>
  <Tab label="Webpack">

  const {ModuleFederationPlugin} = require('@module-federation/enhanced/webpack');
  const {FetchaloPlugin} = require('fetchalo/webpack');

  module.exports = {
    plugins: [
      new FetchaloPlugin('./src/fetchalo.config.js'),
      new ModuleFederationPlugin({
        // other options
        runtimePlugins: [

        ]
      }),
    ],

  ```
  </Tab>
  <Tab label="Module Federation Runtime">

    import {createInstance} from '@module-federation/enhanced/runtime';
    import fetchaloFederation from 'fetchalo/federation';

    const mf = createInstance({
      name: 'host',
      remotes: [
        {
          name: 'remote1',
          entry: 'https://remote.example/mf-manifest.json',
          type: 'module',
        },
      ],
      plugins: [
        fetchaloFederation({

        }),
      ],
    });
    ```

使用 Rspack 或 webpack 时，`FetchaloPlugin` 会把 fetchalo 客户端、[配置文件](#配置文件)和
es-module-shims 插入到每个入口之前，确保它们先于应用执行；`fetchalo/federation` 则通过
fetchalo 加载 manifest 和 remote 入口。

使用 Module Federation 运行时 API 时，直接把 origins 和 headers 传给
`fetchalo/federation`，插件创建时会在页面中安装 fetchalo 和 es-module-shims。也可以使用
`mf.registerPlugins([fetchaloFederation({ ... })])`，只要在第一个 remote 加载之前调用即可。多个实例会共用第一次的安装。在
webpack 或 Rspack 宿主中，请改用构建插件：它可以避免打包工具解析 es-module-shims。

Vite 宿主请将 `fetchalo` Vite 插件与 `@module-federation/vite` 中的
`runtimePlugins: ['fetchalo/federation']` 搭配使用，详见
[fetchalo README](https://github.com/gioboa/fetchalo#usage)。

## 配置文件

构建插件接收一个配置文件（`.js` 或 `.ts`）的路径，并在应用之前于浏览器中加载它。它的默认导出包含：

- `origins`：需要携带请求头的 origin 列表。
- `headers`：每个请求都会调用，因此可以返回刷新后的 token。

```ts title="src/fetchalo.config.ts"
import type { FetchaloConfig } from 'fetchalo';

export default {
  origins: ['https://remote.example'],
  headers: async (url) => ({ Authorization: `Bearer ${await getToken()}` }),
} satisfies FetchaloConfig;
```

配置文件不能导入 `origins` 中的文件。它会和应用一起打包，因此可以读取 `DefinePlugin`
常量等构建期的值。如果需要在浏览器中计算配置，可以导出一个返回配置（或配置 Promise）的函数：

```ts title="src/fetchalo.config.ts"
export default async (): Promise<FetchaloConfig> => ({
  origins: await fetch('/api/remote-origins').then((res) => res.json()),
  headers: (url) => ({ Authorization: `Bearer ${getToken()}` }),
});
```

Module Federation Runtime 标签页中的 `fetchaloFederation()` 同样接受 `{ origins, headers }`
的 Promise。在以 Promise 形式提供的配置 resolve 之前，发往这些 origin 的请求会等待它，配置就绪后
`window.fetchalo.ready` 会 resolve。

## API

```ts
// fetchalo/federation：传入配置时安装 fetchalo；不传时使用构建插件已安装的 fetchalo。
fetchaloFederation(config?: FetchaloConfig | Promise<FetchaloConfig>);

// 构建插件：配置文件的路径。
new FetchaloPlugin(configPath: string); // fetchalo/webpack、fetchalo/rspack
fetchalo(configPath: string); // Vite

// 配置文件的默认导出：
export default FetchaloConfig | (() => FetchaloConfig | Promise<FetchaloConfig>);

type FetchaloConfig = {
  origins: string[];
  headers: (url: string) => HeadersInit | undefined | Promise<HeadersInit | undefined>;
};
```

## CORS

remote 服务端需要响应该请求头的 CORS 预检请求，返回 `Access-Control-Allow-Origin` 和
`Access-Control-Allow-Headers: Authorization`。

## 覆盖的请求

对于配置的 `origins` 下的文件：

| 请求                                                                      | 加载方式                                                                                       |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| JS 模块：入口、静态 import、`import()`                                    | [es-module-shims](https://github.com/guybedford/es-module-shims) 的 shim 模式及其 `fetch` 钩子 |
| Module Federation manifest 和 remote 入口                                 | `fetchalo/federation` 运行时插件                                                               |
| `<link rel="stylesheet">` 及其 `@import`                                  | fetch 后通过 `blob:` URL 提供                                                                  |
| 上述样式表中的 `url()`、`<style>` 文本、CSSOM 规则（CSS-in-JS）和内联样式 | 改写为 `blob:` URL                                                                             |
| `<img>`、`<source>`、`<video>`、`<audio>` 的 `src`、`srcset`、`poster`    | fetch 后通过 `blob:` URL 提供                                                                  |

指向这些 origin 的 `<link rel="modulepreload|preload|prefetch">` 提示会被移除：模块由
es-module-shims 获取，其他文件在使用时获取。

## 限制

- 仅支持浏览器，不支持 SSR。
- 仅支持构建产物中的 `module`/`esm` 类型 remote。`var` 类型的 remote 通过 `<script>`
  标签加载，无法携带请求头。
- 不覆盖：页面 HTML 中直接写入的元素、SVG `<image>`、`<iframe>`、`<object>`、worker、
  `adoptedStyleSheets`、通过 `innerHTML` 创建的元素，以及被加载代码自身发起的 `fetch()` 调用。
- 媒体资源会被完整下载为 `blob:` URL：不支持流式加载和 range 请求。`blob:` URL 在页面生命周期内保留。
- 它会修改 DOM 原型（`appendChild`、`setAttribute`、`insertRule`、媒体属性 setter），但只作用于配置的 origin。
