## Retry-Plugin {#retry-plugin}

Das Retry-Plugin bietet einen robusten Wiederholungsmechanismus für Module Federation. Wenn Remote-Module oder Ressourcen nicht geladen werden können, versucht es den Ladevorgang automatisch erneut, um deine Anwendung stabil zu halten.

## Funktionen {#features}

- **Automatische Wiederholungsversuche**: Fehlgeschlagene Ladevorgänge wiederholen und dadurch die Stabilität erhöhen
- **Domain-Wechsel**: Automatisch zwischen mehreren Ersatz-Domains wechseln
- **Cache-Busting**: Query-Parameter ergänzen, damit der Cache erneute Versuche nicht beeinträchtigt
- **Flexible Konfiguration**: Anzahl, Wartezeit und Callbacks der Wiederholungsversuche anpassen

## Installation {#install}

```bash
npm install @module-federation/retry-plugin
```

## Migrationsanleitung {#migration-guide}

### Von v0.18.x auf v0.19.x {#from-v018x-to-v019x}

Die Plugin-Konfiguration wurde vereinfacht. Die bisherigen Konfigurationsobjekte `fetch` und `script` sind veraltet:

```ts
// ❌ Old way (deprecated)
RetryPlugin({
  fetch: {
    url: 'http://localhost:2008/not-exist-mf-manifest.json',
    fallback: () => 'http://localhost:2001/mf-manifest.json',
  },
  script: {
    url: 'http://localhost:2001/static/js/async/src_App_tsx.js',
    customCreateScript: (url, attrs) => { /* ... */ },
  }
})

// ✅ New way
RetryPlugin({
  retryTimes: 3,
  retryDelay: 1000,
  domains: ['http://localhost:2001'],
  manifestDomains: ['http://localhost:2001'],
  addQuery: ({ times, originalQuery }) => `${originalQuery}&retry=${times}`,
})
```

## Verwendung {#usage}
### Methode 1: Im Build-Plugin {#method1-used-in-the-build-plugin}

```ts title="rspack.config.ts"
import { pluginModuleFederation } from '@module-federation/rsbuild-plugin';
import { defineConfig } from '@rsbuild/core';

export default defineConfig({
  plugins: [
    pluginReact(),
    pluginModuleFederation({
      runtimePlugins: [
        path.join(__dirname, './src/runtime-plugin/retry.ts'),
      ],
    }),
  ],
});

```

```ts
// ./src/runtime-plugin/retry.ts
import { RetryPlugin } from '@module-federation/retry-plugin';
const retryPlugin = () => RetryPlugin({
  retryTimes: 3,
  retryDelay: 1000,
  manifestDomains: ['https://domain1.example.com', 'https://domain2.example.com'],
  domains: ['https://cdn1.example.com', 'https://cdn2.example.com'],
  addQuery: ({ times, originalQuery }) => `${originalQuery}&retry=${times}`,
  onRetry: ({ times, url }) => console.log('retry', times, url),
  onSuccess: ({ url }) => console.log('success', url),
  onError: ({ url }) => console.log('error', url),
})
export default retryPlugin;
```

## Konfiguration {#configuration}

### Grundlagen {#basic}

**retryTimes**
- Typ: `number`
- Optional
- Anzahl der Wiederholungsversuche, standardmäßig 3

**retryDelay**
- Typ: `number`
- Optional
- Wartezeit zwischen Wiederholungsversuchen in Millisekunden, standardmäßig 1000

### Erweiterte Optionen {#advanced}

**domains**
- Typ: `string[]`
- Optional
- Ersatz-Domains, zwischen denen gewechselt wird. Standardmäßig ein leeres Array

**addQuery**
- Typ: `boolean | ((context: { times: number; originalQuery: string }) => string)`
- Optional
- Legt fest, ob bei Wiederholungsversuchen ein Query-Parameter angehängt wird
- Für Remote-Entries vom Typ `esm` und `module` ist Cache-Busting standardmäßig aktiviert, weil Browser fehlgeschlagene dynamische Imports anhand der URL zwischenspeichern. Andere Wiederholungspfade ergänzen standardmäßig keinen Query-Parameter
- Mit `addQuery: false` deaktivierst du das standardmäßige Cache-Busting für ESM-/Module-Remote-Entries
- Wenn du eine Funktion übergibst, erhält sie die Anzahl der Wiederholungsversuche und den ursprünglichen Query-String und soll den neuen Query-String zurückgeben

**fetchOptions**
- Typ: `RequestInit`
- Optional
- Eigene Fetch-Optionen, standardmäßig ein leeres Objekt

**manifestDomains**
- Typ: `string[]`
- Optional
- Liste für Domain-Wechsel beim Abrufen des Manifests, zum Beispiel `mf-manifest.json`. Bei erneuten Manifest-Anfragen hat sie Vorrang vor `domains`. Andere Ressourcen verwenden weiterhin `domains`.

### Callbacks {#callbacks}

**onRetry**
- Typ: `({ times, domains, url, tagName }: { times?: number; domains?: string[]; url?: string; tagName?: string }) => void`
- Optional
- Wird bei jedem Wiederholungsversuch aufgerufen
- Parameter: `times` ist die aktuelle Nummer des Wiederholungsversuchs, `domains` die Domain-Liste, `url` die Anfrage-URL und `tagName` der Ressourcentyp

**onSuccess**
- Typ: `({ domains, url, tagName }: { domains?: string[]; url?: string; tagName?: string; }) => void`
- Optional
- Wird aufgerufen, wenn ein Wiederholungsversuch erfolgreich ist
- Parameter: `domains` ist die Domain-Liste, `url` die Anfrage-URL und `tagName` der Ressourcentyp

**onError**
- Typ: `({ domains, url, tagName }: { domains?: string[]; url?: string; tagName?: string; }) => void`
- Optional
- Wird aufgerufen, wenn alle Wiederholungsversuche scheitern
- Parameter: `domains` ist die Domain-Liste, `url` die Anfrage-URL und `tagName` der Ressourcentyp

## Details {#details}

### Wiederholungslogik {#retry-logic}

Das Plugin versucht das Laden einer Ressource automatisch erneut, wenn es fehlschlägt. `retryTimes` legt die Anzahl der Wiederholungsversuche fest. Zum Beispiel:

- `retryTimes: 3` bedeutet bis zu 3 Wiederholungsversuche nach dem ersten Versuch.
- Vor jedem Wiederholungsversuch wird `retryDelay` ms gewartet.

### Domain-Wechsel {#domain-rotation}

Wenn `domains` konfiguriert ist, wechselt das Plugin bei jedem Wiederholungsversuch den Host:

```javascript
const retryPlugin = RetryPlugin({
  domains: [
    'https://cdn1.example.com',
    'https://cdn2.example.com',
    'https://cdn3.example.com'
  ],
});
```

Reihenfolge der Versuche:
1. Erster Versuch: ursprüngliche URL
2. Erster Wiederholungsversuch: Wechsel zu `cdn2.example.com`
3. Zweiter Wiederholungsversuch: Wechsel zu `cdn3.example.com`
4. Dritter Wiederholungsversuch: Wechsel zu `cdn1.example.com`

### Cache-Busting {#cache-busting}

Mit `addQuery` kannst du bei Wiederholungsversuchen Query-Parameter ergänzen, um Cache-Einflüsse zu vermeiden:

Bei Remote-Entries vom Typ `esm` oder `module` ergänzt das Plugin standardmäßig `retryCount`. So verwendet jeder erneute dynamische Import eine neue URL. Diese Voreinstellung betrifft keine Manifest-, Fetch- oder klassischen Script-Wiederholungen. Bei Bedarf kannst du sie ausdrücklich deaktivieren:

```javascript
const retryPlugin = RetryPlugin({
  addQuery: false,
});
```

So aktivierst du Cache-Busting für alle Wiederholungspfade:

```javascript
const retryPlugin = RetryPlugin({
  addQuery: true, // adds ?retryCount=1, ?retryCount=2, etc.
});
```

Du kannst auch eine Funktion übergeben:

```javascript
const retryPlugin = RetryPlugin({
  addQuery: ({ times, originalQuery }) => {
    return `${originalQuery}&retry=${times}&timestamp=${Date.now()}`;
  },
});
```

### Callbacks {#callbacks-1}

Mit Callbacks kannst du den Ablauf der Wiederholungsversuche beobachten:

```javascript
const retryPlugin = RetryPlugin({
  onRetry: ({ times, domains, url, tagName }) => {
    console.log(`Retry #${times}, domains: ${domains}, url: ${url}`);
  },
  onSuccess: ({ domains, url, tagName }) => {
    console.log(`Retry success, domains: ${domains}, url: ${url}`);
  },
  onError: ({ domains, url, tagName }) => {
    console.log(`Retry failed, domains: ${domains}, url: ${url}`);
  },
});
```

Callback-Parameter:
- `times`: aktuelle Nummer des Wiederholungsversuchs, beginnend bei 1
- `domains`: aktuelle Domain-Liste
- `url`: URL der aktuellen Anfrage
- `tagName`: Ressourcentyp ('fetch' oder 'script')

## Anwendungsfälle {#use-cases}

### 1. CDN-Failover {#1-cdn-failover}

```javascript
const retryPlugin = RetryPlugin({
  retryTimes: 2,
  domains: [
    'https://cdn1.example.com',
    'https://cdn2.example.com',
    'https://cdn3.example.com'
  ],
  addQuery: true,
});
```

### 2. Instabile Netzwerke {#2-unstable-networks}

```javascript
const retryPlugin = RetryPlugin({
  retryTimes: 5,
  retryDelay: 2000,
  onRetry: ({ times }) => {
    console.log(`Unstable network, retry #${times}`);
  },
});
```

### 3. Monitoring und Logging {#3-monitoring-and-logging}

```javascript
const retryPlugin = RetryPlugin({
  onRetry: ({ times, url }) => {
    analytics.track('resource_retry', { times, url });
  },
  onError: ({ url }) => {
    logger.error('Resource load failed after all retries', { url });
  },
});
```

## Hinweise {#notes}

1. **Performance**: Viele Wiederholungsversuche erhöhen die Ladezeit. Passe die Anzahl an deine Umgebung an.
2. **Domains**: Stelle sicher, dass alle Domains in `domains` dieselbe Ressource ausliefern.
3. **Caching**: Berücksichtige bei aktiviertem `addQuery` die Caching-Strategie des CDNs.
4. **Fehlerbehandlung**: Wenn alle Wiederholungsversuche scheitern, wird der ursprüngliche Fehler ausgelöst. Behandle ihn im aufrufenden Code.

## Fehlercodes {#error-codes}

- `RUNTIME_008`: Fehler beim Laden einer Ressource, der den Wiederholungsmechanismus auslöst
