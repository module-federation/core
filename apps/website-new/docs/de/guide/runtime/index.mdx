# Runtime verwenden {#runtime-access}

:::info Vorwissen

- Die [Funktionen und Möglichkeiten](/guide/start/index.html) von Module Federation
- Das [Glossar](/guide/start/glossary.html) von Module Federation
- Wie du [Module verwendest und exportierst](/guide/start/quick-start.html)

:::

`Module Federation` bietet derzeit zwei Möglichkeiten, Module zu registrieren und zu laden:

- Du deklarierst sie im Build-Plugin (in der Regel in der Datei `module-federation.config.ts`).

- Du registrierst und lädst sie direkt über die `runtime`-API.

Beide Ansätze lassen sich kombinieren. Du kannst je nach Anwendungsfall entscheiden, wie und wann du Module registrierst.

## Unterschiede zwischen den Ansätzen {#differences-between-the-two-approaches}

| Module zur Laufzeit registrieren | Module im Build-Plugin registrieren |
| --- | --- |
| Funktioniert ohne Build-Plugin; auch Projekte mit `webpack4` können Module direkt über die Runtime registrieren und laden | Benötigt eine passende Build-Integration, etwa für Webpack 5 oder Rspack; siehe [Integrationen](/integrations/index.html) |
| Unterstützt die dynamische Registrierung von Modulen | Deklariert Remotes zunächst im Build; zusätzliche Remotes lassen sich über die Runtime-API registrieren |
| Die Runtime allein verarbeitet keine `import`-Anweisungen für Remote-Module | Die Build-Integration verarbeitet statische und dynamische `import`-Anweisungen für konfigurierte Remotes |
| Unterstützt das Laden von Modulen mit `loadRemote` | Unterstützt das Laden von Modulen mit `loadRemote` |
| Für `shared` sind konkrete Versionsinformationen sowie eine Funktion zum Bereitstellen oder Laden der Abhängigkeit erforderlich | Für `shared` genügt die Konfiguration von Regeln; die Build-Integration ergänzt Versionen und Ladefunktionen |
| Shared-Abhängigkeiten werden über die Runtime-API nach den angegebenen Versions- und Scope-Regeln bereitgestellt und wiederverwendet | Die Build-Integration verbindet die Shared-Abhängigkeiten der beteiligten Anwendungen mit der Runtime |
| Der Ladevorgang lässt sich über Runtime-Plugins beeinflussen | Der Ladevorgang lässt sich ebenfalls über `runtimePlugins` und die Runtime-API beeinflussen |
| Die Runtime allein lädt keine Remote-Typinformationen für den Editor herunter | Die Build-Integration unterstützt das Erzeugen und Laden von Remote-Typinformationen |

## Installation

Je nach Projekttyp verwendest du unterschiedliche Pakete und Importpfade für die Runtime. In den meisten Projekten installierst du `@module-federation/enhanced` und importierst die Runtime-APIs aus `@module-federation/enhanced/runtime`. Wenn dein Modern.js-Projekt bereits ein Module-Federation-Plugin verwendet, importiere die Runtime-APIs über dessen `/runtime`-Einstiegspunkt. So verwenden das Framework-Plugin und manuelle Runtime-Aufrufe dieselbe Runtime-Instanz.

import { PackageManagerTabs, Tab, Tabs } from '@theme';

## Module registrieren {#module-registration}

<Tabs>
  <Tab label="Mit Build-Plugin">
  ```tsx
  // If use build plugin, you can use `registerRemotes` directly.
  import { registerRemotes } from '@module-federation/enhanced/runtime';

  registerRemotes([
    {
        name: 'remote1',
        alias: 'remote-1',
        entry: 'http://localhost:3001/mf-manifest.json',
    }
  ]);
  ```
  </Tab>
  <Tab label="Nur Runtime (ohne Build-Plugin)">
  ```ts
  // If not use build plugin, you can create new instance and register remote.
  import { createInstance } from '@module-federation/enhanced/runtime';

  const mf = createInstance({
    name: 'mf_host',
    remotes: [
      {
        name: 'remote1',
        alias: 'remote-1',
        entry: 'http://localhost:3001/mf-manifest.json',
      }
    ]
  });

  mf.registerRemotes([
    {
        name: 'remote1',
        alias: 'remote-1',
        entry: 'http://localhost:3001/mf-manifest.json',
    }
  ]);
  ```
  </Tab>
</Tabs>

## Module laden {#module-loading}

<Tabs>
  <Tab label="Mit Build-Plugin">
  ```tsx
  // If use build plugin, you can use `loadRemote` directly.
  import { loadRemote } from '@module-federation/enhanced/runtime';
  import React from 'react';

  export default () => {
    const MyButton = React.lazy(() =>
      loadRemote('remote1').then(({ MyButton }) => {
        return {
          default: MyButton
        };
      }),
    );

    return (
      <React.Suspense fallback="Loading Button">
        <MyButton />
      </React.Suspense>
    );
  }
  ```
  </Tab>
  <Tab label="Nur Runtime (ohne Build-Plugin)">
  ```ts
  // If not use build plugin, you can create new instance and load remote.
  import { createInstance } from '@module-federation/enhanced/runtime';
  import React from 'react';

  const mf = createInstance({
    name: 'mf_host',
    remotes: [
      {
        name: 'remote1',
        alias: 'remote-1',
        entry: 'http://localhost:3001/mf-manifest.json',
      }
    ]
  });

  export default () => {
    const MyButton = React.lazy(() =>
      mf.loadRemote('remote1').then(({ MyButton }) => {
        return {
          default: MyButton
        };
      }),
    );

    return (
      <React.Suspense fallback="Loading Button">
        <MyButton />
      </React.Suspense>
    );
  }
  ```

### Anonyme Module laden {#loading-anonymous-modules}

<Tabs>
    <Tab label="Mit Build-Plugin">
    ```tsx
    // If use build plugin, you can use `loadRemote` directly.
    import React from 'react';
    import { loadRemote } from '@module-federation/enhanced/runtime';

    const RemoteButton = React.lazy(() => loadRemote('provider/button'));
    // It can also be loaded via its module alias:
    // const RemoteButton = React.lazy(() => loadRemote('remotes-1/button'));

    export default () => {
      return (
        <React.Suspense fallback="Loading Button">
          <RemoteButton />
        </React.Suspense>
      );
    }
    ```
    </Tab>
    <Tab label="Nur Runtime (ohne Build-Plugin)">
    ```tsx
    // If not use build plugin, you can create new instance and load remote.
    import { createInstance } from '@module-federation/enhanced/runtime';
    import React from 'react';

    // Create an instance
    const mf = createInstance({
      name: 'mf_host',
      remotes: [
        {
          name: 'remote1',
          alias: 'remote-1',
          entry: 'http://localhost:3001/mf-manifest.json',
        }
      ]
    });

    // Use instance api load remote.
    const RemoteButton = React.lazy(() => mf.loadRemote('provider/button'));
    // Also support use alias to load
    // const RemoteButton = React.lazy(() => mf.loadRemote('remotes-1/button'));

    export default () => {
      return (
        <React.Suspense fallback="Loading Button">
          <RemoteButton />
        </React.Suspense>
      );
    }
    ```
    </Tab>
 </Tabs>

### Hilfsfunktionen laden {#loading-utility-functions}

<Tabs>
    <Tab label="Mit Build-Plugin">
    ```tsx
    // If use build plugin, you can use `loadRemote` directly.
    import React from 'react';
    import { loadRemote } from '@module-federation/enhanced/runtime';

    // Load the util exposed by remote1
    loadRemote<{add: (...args: Array<number>)=> number }>("remote1/util").then((md)=>{
        md.add(1,2);
    });
    ```
    </Tab>
