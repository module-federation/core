# Globale Variablen {#global-variables}

Die wichtigsten globalen Variablen in {props.name || 'Module Federation'} sind `__FEDERATION__`, <code>{props.shareVar || 'SHARE'}</code> und <code>{props.instanceVar || 'INSTANCES'}</code>. Sie enthalten die Module-Federation-Informationen, Shared-Modulinformationen und Instanzinformationen der aktuellen Anwendung. Damit kannst du das Runtime-Verhalten von Module Federation nachvollziehen und Fehler untersuchen.

:::warning Hinweis
Globale Variablen sind schreibgeschützt. Ändere sie nicht.
:::

## **FEDERATION**

Nach der Initialisierung wird die Variable `__FEDERATION__` global eingefügt. Dieses Objekt enthält alle Module-Federation-Informationen der aktuellen Anwendung.

### moduleInfo

import Collapse from '@components/Collapse';

:::tip
Verwende am besten die [Chrome Devtools](/guide/debug/chrome-devtool.html), um die aufbereiteten `moduleInfo`-Daten anzusehen.
:::

Enthält alle Modulinformationen der aktuellen Anwendung. Daraus kannst du die Abhängigkeiten der Module ermitteln.

Die Struktur von `moduleInfo` ist ein Objekt, dessen Schlüssel aus zwei Teilen bestehen: `{moduleName}(:{moduleVersion})`.

- `moduleName` ist der Modulname; `moduleVersion` ist die Version des Moduls oder seine `url`.

- `moduleVersion` existiert nur bei Producer-Modulen.

Im obigen Beispiel enthält `moduleInfo` Informationen zu 5 Modulen. Auf `manifest_host` folgt keine Versionsnummer; daran erkennst du, dass es sich um ein Consumer-Modul handelt.

Das Feld `remotesInfo` in `manifest_host` enthält Informationen zu allen Producer-Modulen, von denen es abhängt. Das zugehörige Feld `matchedVersion` hält die passende Version oder `url` fest.

Die Informationen zum jeweiligen Producer-Modul findest du über den Schlüssel zusammen mit `matchedVersion` im Feld `remotesInfo` des Consumers, etwa `webpack_provider:http://localhost:3009/mf-manifest.json`.

#### version

> Existiert nur bei Producern; bei Consumern ist der Wert eine leere Zeichenfolge.

Die Version oder URL des aktuellen Moduls.

#### buildVersion

Die Build-Version des aktuellen Moduls, in der Regel aus dem Feld `version` in `package.json`.

#### globalName

> Existiert nur beim Producer.

Der Name der globalen Variablen des aktuellen Producer-Moduls. Über globalThis[globalName] kannst du auf den Container des Producers zugreifen. Der Name stammt in der Regel aus dem Feld `name` in `package.json`.

#### publicPath

Der publicPath des aktuellen Moduls.

#### getPublicPath

> Dieses Feld und `publicPath` schließen sich gegenseitig aus.

Der getPublicPath des aktuellen Moduls. Den endgültigen publicPath erhältst du durch den Aufruf `new Function(getPublicPath)()`.

#### ssrPublicPath

Der publicPath der Serverdatei des aktuellen Moduls.

#### remoteEntry

> Existiert nur beim Producer.

Der Name der Entry-Datei des aktuellen Producer-Moduls.

#### remoteEntryType

> Existiert nur beim Producer.

Der Typ der Entry-Datei des aktuellen Producer-Moduls.

#### remoteTypesZip

> Existiert nur beim Producer.

Der Name des komprimierten Archivs mit der Typdeklarationsdatei des aktuellen Producer-Moduls.

#### remoteTypesAPI

> Existiert nur beim Producer.

Der Name der Typ-API-Deklarationsdatei des aktuellen Producer-Moduls.

#### shared

Informationen zu allen Shared-Modulen, von denen das aktuelle Modul abhängt. Die Typdefinition lautet:

```ts
type Shared = Array<{
  sharedName: string;
  version?: string;
  assets: {
    js: {
      sync: string[];
      async: string[];
    };
    css: {
      sync: string[];
      async: string[];
    };
  };
}>;
```

#### modules

> Existiert nur beim Producer.

Informationen zu allen vom aktuellen Modul exportierten Modulen. Die Typdefinition lautet:

```ts
type Modules = Array<{
  moduleName: string;
  modulePath: string;
  assets: {
    js: {
      sync: string[];
      async: string[];
    };
    css: {
      sync: string[];
      async: string[];
    };
  };
}>;
```

### **SHARE**

Informationen zu allen aktuell registrierten (geladenen) Shared-Modulen. Die Typdefinition lautet:

```ts
type GlobalShareScopeMap = {
  [instanceName: string]: {
    [scope: string]: {
      [pkgName: string]: {
        [sharedVersion: string]: {
          version: string;
          get: (() => () => Module) | (() => Promise<() => Module>);
          shareConfig: {
            singleton?: boolean;

          scope: Array<string>;
          useIn: Array<string>;
          from: string;
          deps: Array<string>;
          lib?: () => Module;
          loaded?: boolean;

           * @deprecated set in initOptions.shareStrategy instead

};
```

1. Für `react` gibt es nur die Version `18.3.1`.

4. Sieh dir schließlich `useIn` an: Es enthält `webpack_provider` und `app1`. Beide Module verwenden also diese Version von `react`.

### **INSTANCES**

Die aktuell geladene MF-Instanz. Sie speichert eine Liste aller geladenen MF-Module. Jeder Listeneintrag hat die folgende Struktur:

#### bridgeHook

Enthält Metadaten zur MF-Bridge, die das korrekte Laden anwendungsübergreifender Anwendungsfälle mit React und Vue ermöglicht.

#### hooks

Enthält Metadaten zu den MF-Hooks, mit denen du dich in den MF-Lifecycle einklinkst.

#### loaderHook

Enthält Metadaten zum MF-loaderHook.

#### moduleCache

Enthält eine Map aller im moduleCache verfügbaren MF-Module und ihrer Metadaten.

#### name

Der Name des MF-Moduls.

#### options

> Hilfreich bei der Fehlersuche in deinen Modulen.

Zentrale Daten zum MF-Modul, etwa geladene Plugins, verbundene Remotes, shareStrategy und das Objekt mit den Shared-Abhängigkeiten.

#### remoteHandler

Enthält Metadaten zum MF-remoteHandler einschließlich idToRemoteMap. Diese Map enthält alle Bindungen zu Remote-Komponenten, die von den verbundenen MF-Remotes bereitgestellt werden.

#### shareScopeMap

Enthält Metadaten zum MF-Share-Scope einschließlich Informationen zu jeder verbundenen Shared-Abhängigkeit.

#### sharedHandler

Enthält Metadaten zum MF-sharedHandler.

#### snapshotHandler

> Hilfreich, um Struktur und Status von mf-manifest.json zu prüfen.

Enthält Metadaten zum MF-snapshotHandler einschließlich der Objekte manifestCache und manifestLoading.

#### version

Die Version des MF-Moduls.

### **PRELOADED_MAP**

Die Schlüssel-Wert-Map aller beim Build vorgeladenen Module. `key` steht für den Modulnamen; `value` ist ein boolescher Wert, der den Ladestatus angibt.

### **MANIFEST_LOADING**

Enthält Metadaten zum Objekt manifestLoading. Dies entspricht `snapshotHandler.manifestLoading` in `__INSTANCES__`.
