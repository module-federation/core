# Überblick zur Next.js-Integration {#nextjs-integration-overview}

:::danger Projekt wird eingestellt
Die Unterstützung für Next.js läuft aus. [Mehr erfahren](https://github.com/module-federation/core/issues/3153)

Dieses Plugin ermöglicht Module Federation in Next.js.

## Unterstützt {#supports}

- next ^15 || ^14 || ^13 || ^12
- Serverseitiges Rendering
- Pages Router

Diese Beispielanwendung zeigt die Möglichkeiten der Integration:
https://github.com/module-federation/module-federation-examples

## Voraussetzung {#requirement}

Das Plugin setzt intern `process.env.NEXT_PRIVATE_LOCAL_WEBPACK = 'true'`. Am besten setzt du die Variable jedoch in der Umgebung oder über einen Export in der Kommandozeile.

„Local Webpack“ bedeutet, dass webpack als Abhängigkeit installiert sein muss. Next verwendet dann nicht seine mitgelieferte webpack-Kopie. Diese ist hier ungeeignet, da das Plugin Zugriff auf alle internen webpack-APIs benötigt.

- `cross-env NEXT_PRIVATE_LOCAL_WEBPACK=true next dev` oder `next build`
- `npm install webpack`

## Verwendung {#usage}

```js
import React, { lazy } from 'react';
const SampleComponent = lazy(() => import('next2/sampleComponent'));
```

Verwende zum verzögerten Laden föderierter Komponenten `React.lazy` statt `next/dynamic`, um Hydratisierungsfehler zu vermeiden.

## Optionen {#options}

Dieses Plugin funktioniert genau wie ModuleFederationPlugin. Verwende es wie gewohnt.
React und Next-interne Pakete werden bereits automatisch geteilt.

NextFederationPlugin besitzt außerdem das optionale Argument `extraOptions`, mit dem du zusätzliche Funktionen aktivieren kannst:

```js
new NextFederationPlugin({
  name: '',
  filename: '',
  remotes: {},
  exposes: {},
  shared: {},
  extraOptions: {
    debug: boolean, // `false` by default
    exposePages: boolean, // `false` by default
    enableImageLoaderFix: boolean, // `false` by default
    enableUrlLoaderFix: boolean, // `false` by default
    skipSharingNextInternals: boolean, // `false` by default
    scriptTimeout: number // `8000` by default
  },
});
```

- `debug` – Aktiviert den Debug-Modus und gibt zusätzliche Informationen zu internen Abläufen aus.
- `exposePages` – Stellt automatisch alle Next.js-Seiten sowie ihre `./pages-map` bereit.
- `enableImageLoaderFix` – Ergänzt den öffentlichen Hostnamen bei allen von `nextjs-image-loader` gebündelten Assets. Wenn du remoteEntry über `http://example.com` auslieferst, erhalten alle gebündelten Assets diesen Hostnamen zur Laufzeit. Das ähnelt der Basis-URL in HTML, gilt aber für föderierte Module.
- `enableUrlLoaderFix` – Ergänzt den öffentlichen Hostnamen bei allen von `url-loader` gebündelten Assets.
- `skipSharingNextInternals` – Deaktiviert das Teilen Next-interner Pakete. Verwende die Option, wenn du diese selbst teilen oder das Plugin in Anwendungen ohne Next einsetzen möchtest.
- `scriptTimeout` – Timeout in Millisekunden für jeden Ladeversuch des Remote-Entry-Skripts im Browser. Standardwert ist `8000`; Werte, die keine positiven endlichen Zahlen sind, fallen auf diesen Standard zurück. Erhöhe den Wert bei langsamen Verbindungen und verwende [`@module-federation/retry-plugin`](/plugin/plugins/retry-plugin), um vorübergehende Fehler erneut zu versuchen. Diese Option aktiviert keine Wiederholungsversuche und verändert keine Timeouts für serverseitiges Laden.

Next.js leitet die Expose-Asset-Felder für das ältere `flushChunks()` aus `mf-manifest.json` ab, ohne die Webpack-Stats zusätzlich zu durchlaufen. So funktionieren Anwendungen mit älteren Versionen bei schrittweisen Upgrades weiter. Eigene Werkzeuge, die andere ältere Stats-Felder lesen, sollten auf `mf-manifest.json` umgestellt werden. Mit `manifest: false` bleibt die vollständige ältere Ausgabe erhalten.

## Plugin einbinden {#implementing-the-plugin}

1. Verwende `NextFederationPlugin` in der `next.config.js` der Anwendung, aus der du Module bereitstellen möchtest. Wir nennen sie „next2“.

```js
// next.config.js
// either from default
const NextFederationPlugin = require('@module-federation/nextjs-mf');

module.exports = {
  webpack(config, options) {
    const { isServer } = options;
    config.plugins.push(
      new NextFederationPlugin({
        name: 'next2',
        remotes: {
          next1: `next1@http://localhost:3001/_next/static/${
            isServer ? 'ssr' : 'chunks'
          }/remoteEntry.js`,
        },
        filename: 'static/chunks/remoteEntry.js',
        exposes: {
          './title': './components/exposedTitle.js',
          './checkout': './pages/checkout',
        },
        shared: {
          // whatever else
        },
      }),
    );

    return config;
  },
};
```

```js
// next.config.js

const NextFederationPlugin = require('@module-federation/nextjs-mf');

module.exports = {
  webpack(config, options) {
    const { isServer } = options;
    config.plugins.push(
      new NextFederationPlugin({
        name: 'next1',
        remotes: {
          next2: `next2@http://localhost:3000/_next/static/${
            isServer ? 'ssr' : 'chunks'
          }/remoteEntry.js`,
        },
      }),
    );

    return config;
  },
};
```

4. Verwende react.lazy, die Low-Level-API oder require/import, um Remotes zu importieren.

```js
import React, { lazy } from 'react';

const SampleComponent = lazy(() =>
  window.next2.get('./sampleComponent').then((factory) => {
    return { default: factory() };
  }),
);

// or

const SampleComponent = lazy(() => import('next2/sampleComponent'));

//or

import Sample from 'next2/sampleComponent';
```

## RuntimePlugins {#runtimeplugins}

Für Erweiterungen und „Middleware“ für Federation kannst du `@module-federation/enhanced/runtime` verwenden:

```js
// next.config.js
new NextFederationPlugin({
  runtimePlugins: [require.resolve('./path/to/myRuntimePlugin.js')],
});
```

## Hilfsfunktionen {#utilities}

`loadRemote` wurde entfernt. Verwende stattdessen die neuen Runtime-APIs: https://module-federation.io/guide/runtime/runtime-api.html#loadremote

**revalidate**

Ermöglicht Hot Reloading des Node-Servers (nicht des Clients) in Produktion.
Das wird empfohlen: Ohne diese Funktion können Server Remote-Updates erst nach einem vollständigen Neustart abrufen.

Weitere Informationen: https://github.com/module-federation/nextjs-mf/tree/main/packages/node#utilities

```js
// __document.js

import { revalidate } from '@module-federation/nextjs-mf/utils';
import Document, { Html, Head, Main, NextScript } from 'next/document';
class MyDocument extends Document {
  static async getInitialProps(ctx) {
    const initialProps = await Document.getInitialProps(ctx);

    // can be any lifecycle or implementation you want
    ctx?.res?.on('finish', () => {
      revalidate().then((shouldUpdate) => {
        console.log('finished sending response', shouldUpdate);
      });
    });

    return initialProps;
  }
  render() {
    return (
      <Html>
        <Head />
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    );
  }
}
```
