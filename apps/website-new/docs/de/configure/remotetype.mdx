# remoteType

`remoteType` legt den externen Modultyp für Remote-Container fest und bestimmt damit, wie die Runtime Remote-Entrys lädt.

- Typ: `ExternalsType`
- Erforderlich: Nein
- Standardwert: `'script'`

```ts
type ExternalsType =
  | 'var' | 'module' | 'assign'
  | 'this' | 'window' | 'self' | 'global'
  | 'commonjs' | 'commonjs2' | 'commonjs-module' | 'commonjs-static'
  | 'amd' | 'amd-require'
  | 'umd' | 'umd2'
  | 'jsonp' | 'system'
  | 'promise' | 'import' | 'module-import'
  | 'script' | 'node-commonjs';
```

## Verwendung {#usage}

`remoteType` steuert, wie webpack/rspack zur Laufzeit die Skripte von Remote-Containern lädt. Gängige Werte:

| Wert | Beschreibung |
|---|---|
| `'script'` | Laden über ein `<script>`-Tag (Standard im Browser) |
| `'var'` | Der Remote-Container wird als globale Variable bereitgestellt |
| `'commonjs2'` | Laden über `require()` (Node.js) |
| `'node-commonjs'` | CommonJS-Format von Node.js |
| `'import'` | Laden über dynamisches `import()` |
| `'promise'` | Laden über einen Promise-Wrapper |
| `'module'` | Laden als ESM-Modul |

:::tip
Meist musst du `remoteType` nicht manuell setzen: Der Standardwert `'script'` funktioniert in Browserumgebungen. Serverseitige Node.js-Anwendungen benötigen in der Regel `'commonjs2'` oder `'node-commonjs'`.
:::

## Beispiel {#example}

```ts
// Browser (default)
new ModuleFederationPlugin({
  name: '@demo/host',
  remoteType: 'script',
  remotes: {
    provider: 'provider@http://localhost:3001/remoteEntry.js',
  },
});

// Node.js server-side
new ModuleFederationPlugin({
  name: '@demo/node-host',
  remoteType: 'commonjs2',
  remotes: {
    provider: 'provider@http://localhost:3001/remoteEntry.js',
  },
});
```
