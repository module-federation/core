# Hooks de runtime

El runtime de Module Federation expone hooks en las etapas clave: la carga de módulos remotos, la inicialización de contenedores, el registro y la resolución de dependencias compartidas, entre otras. Son útiles para diagnóstico y trazado, fallbacks ante errores, reescritura de dependencias compartidas, personalización de la carga de recursos y escenarios similares.

## Valores de retorno de los hooks

En `SyncHook` y `AsyncHook`, devolver `undefined` significa que el plugin solo observa el evento. No borra un valor devuelto por un plugin anterior. Un plugin posterior aún puede sustituir ese valor devolviendo otro valor distinto de `undefined`.

En `SyncWaterfallHook` y `AsyncWaterfallHook`, devuelve el objeto de argumentos completo y actualizado cuando necesites cambiar el payload. Devolver `undefined` conserva los argumentos actuales y los pasa al siguiente plugin.

## afterLoadRemote

`AsyncHook`

Se llama cuando termina una petición de `loadRemote`. Se ejecuta en las cargas correctas, en las fallidas y en las recuperadas por `errorLoadRemote`. Úsalo para registrar el estado final de la carga del remote.

En una carga correcta, `onLoad` se ejecuta antes que `afterLoadRemote`. Si una carga falla y `errorLoadRemote` devuelve un fallback, `afterLoadRemote` recibe el `error` original y `recovered: true`.

```ts
async function afterLoadRemote(args: AfterLoadRemoteOptions): Promise<void>;

type AfterLoadRemoteOptions = {
  id: string;
  expose?: string;
  remote?: RemoteInfo;
  options?: {
    loadFactory?: boolean;
    from?: 'build' | 'runtime';
  };
  error?: unknown;
  recovered?: boolean;
  origin: ModuleFederation;
};
```

## errorLoadRemote

`AsyncHook`

Se llama si falla la carga de remotes y permite gestionar el error de forma personalizada. Puede devolver una lógica de fallback personalizada.

```ts
async function errorLoadRemote(
  args: ErrorLoadRemoteOptions,
): Promise<void | unknown>;

type ErrorLoadRemoteOptions = {
  id: string;
  error: unknown;
  options?: any;
  from: 'build' | 'runtime';
  lifecycle: 'beforeRequest' | 'beforeLoadShare' | 'afterResolve' | 'onLoad';
  remote?: RemoteInfo;
  expose?: string;
  origin: ModuleFederation;
};
```

El parámetro `lifecycle` indica la etapa en la que se produjo el error:

- `beforeRequest`: error durante el procesamiento inicial de la petición
- `afterResolve`: error durante la carga del manifest (el caso más habitual en fallos de red)
- `onLoad`: error durante la carga y ejecución del módulo
- `beforeLoadShare`: error al cargar un remoteEntry durante la inicialización de las dependencias compartidas

Si este hook devuelve un módulo de fallback, el runtime usa ese valor para continuar. Si un plugin de diagnóstico o de logging devuelve `undefined`, no borra el fallback devuelto por otro plugin.

```ts
import { createInstance, loadRemote } from '@module-federation/enhanced/runtime';

import type { ModuleFederationRuntimePlugin } from '@module-federation/enhanced/runtime';

const fallbackPlugin: () => ModuleFederationRuntimePlugin =
  function () {
    return {
      name: 'fallback-plugin',
      errorLoadRemote(args) {
        const { lifecycle, id, error } = args;

        if (error) {
          console.warn(\`Failed to load remote \${id} at \${lifecycle}:\`, error?.message || error);
        }

        switch (lifecycle) {
          case 'afterResolve':
            return {
              id: id || 'fallback',
              name: id || 'fallback',
              metaData: { /* fallback manifest */ },
              shared: [],
              remotes: [],
              exposes: []
            };

          case 'beforeRequest':
            console.warn(\`Request processing failed for \${id}\`);
            return void 0;

          case 'onLoad':
            return () => ({
              __esModule: true,
              default: () => 'Fallback Component'
            });

          case 'beforeLoadShare':
            console.warn(\`Shared dependency loading failed for \${id}\`);
            return () => ({
              __esModule: true,
              default: {}
            });

          default:
            console.warn(\`Unknown lifecycle \${lifecycle} for \${id}\`);
            return void 0;
        }
      },
    };
  };

const mf = createInstance({
    name: 'mf_host',
    remotes: [
        {
            name: "remote",
            alias: "app1",
            entry: "http://localhost:2001/mf-manifest.json"
        }
    ],
    plugins: [fallbackPlugin()]
});

mf.loadRemote('app1/un-existed-module').then(mod=>{
  expect(mod).toEqual('fallback');
});
```

## afterRegisterShare

`SyncHook`

Se llama después de que el runtime intenta registrar una versión de una dependencia compartida
en un share scope. Este hook informa tanto del candidato como del registro que
realmente queda registrado, así que también puede observar conflictos en los que gana un
provider ya existente.

```ts
function afterRegisterShare(args: AfterRegisterShareOptions): void;

type AfterRegisterShareOptions = {
  pkgName: string;
  scope: string;
  shared: Shared;
  previousShared?: Shared;
  registeredShared?: Shared;
  shareScopeMap: ShareScopeMap;
  trigger: 'build' | 'runtime' | 'container-init';
  origin: ModuleFederation;
};
```

- `shared` es el candidato que el runtime intentó registrar.
- `previousShared` es el registro con el mismo scope, paquete y versión antes de
  este intento.
- `registeredShared` es el registro que queda tras resolver el conflicto.
- `trigger` identifica si el registro procede del código de runtime generado en el build,
  de una llamada a la API de runtime o de la inicialización de un contenedor remoto.

`AsyncWaterfallHook`

Se llama antes de cargar shared; se puede usar para modificar la configuración de shared correspondiente.

  shareInfo?: Shared;
  shared: Options['shared'];

type SharedLoadContext = {

## resolveShare

`SyncWaterfallHook`

Permite sobrescribir el resultado final de la selección del módulo compartido.

`resolveShare` se ejecuta después de que el runtime ya haya elegido el scope y la versión candidatos. En este punto, cambiar campos como `scope` o `version` en `args` no cambia por sí solo el resultado final. Para cambiar a otro módulo compartido, sustituye `args.resolver` y devuelve el registro de shared que quieras usar.

```ts
function resolveShare(args: ResolveShareOptions): ResolveShareOptions;

type ResolveShareOptions = {
  shareScopeMap: ShareScopeMap;
  scope: string;
  pkgName: string;
  version: string;
  shareInfo: Shared;
  GlobalFederation: Federation;
  resolver: () =>
    | {
        shared: Shared;
        useTreesShaking: boolean;
      }
    | undefined;
  loadContext?: SharedLoadContext;
};
```

```ts
import {
  createInstance,
  loadRemote,
} from '@module-federation/enhanced/runtime';

import type { ModuleFederationRuntimePlugin } from '@module-federation/enhanced/runtime';

const customSharedPlugin: () => ModuleFederationRuntimePlugin = function () {
  return {
    name: 'custom-shared-plugin',
    resolveShare(args) {
      const { pkgName, shareScopeMap } = args;

      if (pkgName !== 'react') {
        return args;
      }

      const fallbackShared = shareScopeMap.default?.react?.['17.0.0'];
      if (!fallbackShared) {
        return args;
      }

      args.resolver = function () {
        return {
          shared: fallbackShared,
          useTreesShaking: false,
        };
      };
      return args;
    },
  };
};

const mf = createInstance({
  name: 'mf_host',
  shared: {
    react: {
      version: '17.0.0',
      scope: 'default',
      lib: () => React,
      shareConfig: {
        singleton: true,
        requiredVersion: '^17.0.0',
      },
    },
  },
  plugins: [customSharedPlugin()],
});

mf.loadShare('react').then((reactFactory) => {
  expect(reactFactory()).toEqual(React);
});
```

## createScript

`SyncHook`

Se usa para modificar el script al cargar recursos.

```ts
function createScript(args: CreateScriptOptions): CreateScriptHookReturn;

type CreateScriptOptions = {
  url: string;
  attrs?: Record<string, any>;
  remoteInfo?: RemoteInfo;
  resourceContext?: ResourceLoadContext;
};

type CreateScriptHookReturn =
  | HTMLScriptElement
  | { script?: HTMLScriptElement; timeout?: number }
  | void;

type ResourceLoadContext = {
  initiator: 'loadRemote' | 'preloadRemote' | 'loadShare';
  id: string;
  resourceType: 'manifest' | 'remoteEntry' | 'js' | 'css';
  url?: string;
  expose?: string;
};
```

`timeout` se mide en milisegundos y controla el tiempo de espera de la carga del script. El valor por defecto es `20000`.
`resourceContext` indica si la carga de este recurso procede de `loadRemote`,
`preloadRemote` o de la inicialización de shared, además del tipo de recurso, el id y el
módulo expuesto cuando corresponde.
Puedes combinar `timeout` y `resourceContext` para establecer tiempos de espera distintos para
las cargas de remoteEntry y las cargas de precarga.

```ts
import type { ModuleFederationRuntimePlugin } from '@module-federation/enhanced/runtime';

const changeScriptAttributePlugin: () => ModuleFederationRuntimePlugin =
  function () {
    return {
      name: 'change-script-attribute',
      createScript({ url }) {
        if (url === 'http://localhost:3001/remoteEntry.js') {
          let script = document.createElement('script');
          script.src = url;
          script.setAttribute('loader-hooks', 'isTrue');
          script.setAttribute('crossorigin', 'anonymous');
          return {
            script,
            timeout: 30000,
          };
        }
      },
    };
  };
```

## fetch

`AsyncHook`

La función `fetch` permite personalizar la petición que obtiene el JSON del manifest. Una `Response` correcta debe devolver un JSON válido.

```typescript
function fetch(
  manifestUrl: string,
  requestInit: RequestInit,
  remoteInfo?: RemoteInfo,
  resourceContext?: ResourceLoadContext,
): Promise<Response> | void | false;
```

`resourceContext` permite saber si esta petición del manifest procede de
`loadRemote`, `preloadRemote` o de la inicialización de shared.

- Ejemplo para incluir las credenciales al obtener el JSON del manifest:

```ts
import type { FederationRuntimePlugin } from '@module-federation/enhanced/runtime';

// fetch-manifest-with-credentials-plugin.ts
export default function (): FederationRuntimePlugin {
  return {
    name: 'fetch-manifest-with-credentials-plugin',
    fetch(manifestUrl, requestInit) {
      return fetch(manifestUrl, {
        ...requestInit,
        credentials: 'include',
      });
    },
  };
}
```

## createLink

`SyncHook`

Se usa para personalizar el elemento link que se crea para la carga de precargas y estilos.

```ts
function createLink(args: CreateLinkOptions): HTMLLinkElement | void;

type CreateLinkOptions = {
  url: string;
  attrs?: Record<string, any>;
  remoteInfo?: RemoteInfo;
  resourceContext?: ResourceLoadContext;
};

type CreateLinkHookReturn =
  | HTMLLinkElement
  | { link?: HTMLLinkElement; timeout?: number }
  | void;
```

`resourceContext` tiene la misma forma que en `createScript`. Permite distinguir
JS/CSS precargado, la carga real del remoteEntry y el id del recurso relacionado.
`timeout` se mide en milisegundos y controla el tiempo de espera de la carga del link. El
valor por defecto es `20000`.

Ejemplo: usar un tiempo de espera más corto para los recursos de precarga de baja prioridad y, a la vez, mantener
la carga normal de remotes más tolerante.

```ts
import type { ModuleFederationRuntimePlugin } from '@module-federation/enhanced/runtime';

const resourceTimeoutPlugin = (): ModuleFederationRuntimePlugin => ({
  name: 'resource-timeout-plugin',
  createScript({ resourceContext }) {
    if (
      resourceContext?.initiator === 'loadRemote' &&
      resourceContext.resourceType === 'remoteEntry'
    ) {
      return {
        timeout: 30000,
      };
    }
  },
  createLink({ resourceContext }) {
    if (resourceContext?.initiator === 'preloadRemote') {
      return {
        timeout: 5000,
      };
    }
  },
});
```

## getModuleFactory

`AsyncHook`

Se dispara antes de llamar a `remoteEntry.get(expose)` y permite personalizar la resolución de la factoría del módulo.

```ts
async function getModuleFactory(
  args: GetModuleFactoryOptions,
): Promise<(() => Promise<Module>) | undefined>;

type GetModuleFactoryOptions = {
  remoteEntryExports: RemoteEntryExports;
  expose: string;
  moduleInfo: RemoteInfo;
};
```

## loadEntry

`asyncHook`

La función `loadEntry` permite personalizar por completo los remotes, de modo que puedes extender y crear nuevos tipos de remote. Los dos ejemplos sencillos siguientes muestran cómo cargar datos JSON y cómo delegar módulos.

```typescript
function loadEntry(
  args: LoadEntryOptions,
): Promise<RemoteEntryExports | void> | RemoteEntryExports | void;

type LoadEntryOptions = {
  origin: ModuleFederation;
  loaderHook: ModuleFederation['loaderHook'];
  remoteEntryExports?: RemoteEntryExports;
  remoteInfo: RemoteInfo;
  resourceContext?: ResourceLoadContext;
};
interface RemoteInfo {
  name: string;
  version?: string;
  buildVersion?: string;
  entry: string;
  type: RemoteEntryType;
  entryGlobalName: string;
  shareScope: string;
}
export type RemoteEntryExports = {
  get: (id: string) => () => Promise<Module>;
  init: (
    shareScope: ShareScopeMap[string],
    initScope?: InitScope,
    remoteEntryInitOPtions?: RemoteEntryInitOptions,
  ) => void | Promise<void>;
};
```

- Ejemplo de carga de datos JSON

```ts
import { init } from '@module-federation/enhanced/runtime';

import type { FederationRuntimePlugin } from '@module-federation/enhanced/runtime';

// load-json-data-plugin.ts
const changeScriptAttributePlugin: () => FederationRuntimePlugin = function () {
  return {
    name: 'load-json-data-plugin',
    loadEntry({ remoteInfo }) {
      if (remoteInfo.jsonA === 'jsonA') {
        return {
          init(shareScope, initScope, remoteEntryInitOPtions) {},
          async get(path) {
            const json = await fetch(remoteInfo.entry + '.json').then((res) =>
              res.json(),
            );
            return () => ({
              path,
              json,
            });
          },
        };
      }
    },
  };
};
```

```ts
// module-federation-config
{
  remotes: {
    jsonA: "jsonA@https://cdn.jsdelivr.net/npm/@module-federation/runtime/package";
  }
}
```

```ts
// src/bootstrap.js
import jsonA from 'jsonA';
jsonA; // {...json data}
```

- Ejemplo de delegación de módulos

```ts
import { init } from '@module-federation/enhanced/runtime';

import type { FederationRuntimePlugin } from '@module-federation/enhanced/runtime';

// delegate-modules-plugin.ts
const changeScriptAttributePlugin: () => FederationRuntimePlugin = function () {
  return {
    name: 'delegate-modules-plugin',
    loadEntry({ remoteInfo }) {
      if (remoteInfo.name === 'delegateModulesA') {
        return {
          init(shareScope, initScope, remoteEntryInitOPtions) {},
          async get(path) {
            path = path.replace('./', '');
            const { [path]: factory } = await import('./delegateModulesA.js');
            const result = await factory();
            return () => result;
          },
        };
      }
    },
  };
};
```

```ts
// ./src/delegateModulesA.js
export async function test1() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve('test1 value');
    }, 3000);
  });
}
export async function test2() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve('test2 value');
    }, 3000);
  });
}
```

```ts
// module-federation-config
{
  remotes: {
    delegateModulesA: 'delegateModulesA@https://delegateModulesA.js';
  }
}
```

```ts
// src/bootstrap.js
import test1 from 'delegateModulesA/test1';
import test2 from 'delegateModulesA/test2';
test1; // "test1 value"
test2; // "test2 value"
```

## bridgeHook

`bridgeHook` observa las operaciones de renderizado, destrucción y sincronización de rutas
de React Bridge y Vue Bridge. Los paquetes de Bridge pasan un contexto semántico de la operación
como segundo argumento, a la vez que mantienen el primer argumento `info` compatible con
los plugins existentes.

```ts
import type {
  BridgeOperationContext,
  BridgeOperationResult,
} from '@module-federation/bridge-shared';

type BridgeOperationContext = {
  side: 'consumer' | 'producer';
  framework: 'react' | 'vue';
  operation: 'render' | 'update' | 'destroy' | 'route-sync';
  moduleName?: string;
  route?: {
    action: 'memory-route-init' | 'host-to-remote';
    from?: string;
    to?: string;
    basename?: string;
    mechanism?: 'popstate';
  };
  reason?: 'unmount' | 'direct';
};

type BridgeOperationResult = {
  context: BridgeOperationContext;
  result?: unknown;
};
```

## beforeBridgeRender

`SyncHook`

Se dispara antes de que un producer o consumer de Bridge se renderice o se actualice. Puedes
devolver un objeto para ampliar los argumentos de renderizado (por ejemplo, `extraProps`).

## afterBridgeRouteSync

`SyncHook`

Se dispara después de que Bridge sincroniza una ruta. Los consumers de React y Vue informan
de la sincronización de `popstate` del host al remote, mientras que un producer de Vue también informa
de la navegación inicial de la ruta en memoria. `operation.result` contiene el resultado del router
cuando el framework lo proporciona.

```ts
function afterBridgeRouteSync(operation: BridgeOperationResult): void;
```

```ts
import type { ModuleFederationRuntimePlugin } from '@module-federation/enhanced/runtime';

const bridgeTracePlugin = (): ModuleFederationRuntimePlugin => ({
  name: 'bridge-trace-plugin',
  afterBridgeRender(_info, operation) {
    console.log('bridge render', operation?.context);
  },
  afterBridgeRouteSync(operation) {
    console.log('bridge route', operation.context.route);
  },
});
```
