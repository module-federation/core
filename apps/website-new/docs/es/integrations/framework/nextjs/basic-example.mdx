## Configurar el entorno

Antes de empezar, necesitas instalar [Node.js](https://nodejs.org/) y asegurarte de que tu versión de Node.js sea >= 16. **Recomendamos usar la versión LTS de Node.js 24.**

Puedes comprobar la versión de Node.js que estás usando con el siguiente comando:

```bash
node -v
```

Si no tienes Node.js instalado en tu entorno actual, o la versión instalada es demasiado antigua, puedes usar [nvm](https://github.com/nvm-sh/nvm) o [fnm](https://github.com/Schniz/fnm) para instalar la versión necesaria.

Este es un ejemplo de cómo instalar la versión LTS de Node.js 24 mediante nvm:

```bash
# Install the long-term support version of Node.js 24
nvm install 24 --lts

# Make the newly installed Node.js 24 as the default version
nvm alias default 24

# Switch to the newly installed Node.js 24
nvm use 24
```

## Paso 3: implementar SSR {#step-3-implementing-ssr}

<Steps>

### Añadir un ciclo de vida de servidor

Para garantizar que Next.js cree un runtime de servidor, `_document` debe implementar `getInitialProps` o `getServerSideProps`



<div className="rspress-directive warning">
Sin un método de ciclo de vida de servidor, Next intentará aplicar `SSG` a las páginas que considere estáticas.

Sin un runtime de servidor, no hay ningún servidor que renderice las actualizaciones de los remotes
</div>

```jsx title="_document.js"
import Document, { Html, Head, Main, NextScript } from 'next/document';

class MyDocument extends Document {
  static async getInitialProps(ctx) {
    const initialProps = await Document.getInitialProps(ctx);
    return initialProps;
  }

  render() {
    return (
      <Html>
        <Head />
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    );
  }
}
```



### Añadir revalidación para la recarga en caliente en Node

Para gestionar las actualizaciones de los módulos remotos se usa la función `revalidate`. Esto se debe a que Webpack usa una caché de chunks y no volverá a obtener un chunk ya cargado, y un servidor en caliente no reconoce las actualizaciones automáticamente.

Hay dos formas principales de implementar la revalidación:
- Bloqueo del renderizado (Render Blocking)
- Stale While Revalidate

<Tabs>
  <Tab label="Bloqueo del renderizado">
    Esta implementación se recomienda para la mayoría de los casos de uso, ya que ayuda a evitar errores de hidratación al garantizar que el servidor y el cliente estén siempre sincronizados. Al bloquear y comprobar si hay actualizaciones antes de renderizar, puedes garantizar que tu aplicación esté siempre actualizada sin afectar negativamente a la experiencia de usuario.

    **Cómo funciona:**

    - **Antes de renderizar la página**, el servidor comprueba si hay actualizaciones disponibles.
    - **Si hay actualizaciones disponibles**, aplica Hot Module Replacement (HMR) antes de responder a la solicitud del cliente.
    - **Este método garantiza** que todos los usuarios reciban la última versión de la aplicación sin encontrar incoherencias entre el contenido renderizado en el servidor y el renderizado en el cliente.

    **Ejemplo de implementación:**

    ```jsx title="_document"

    import { revalidate } from '@module-federation/nextjs-mf/utils';
    import Document, { Html, Head, Main, NextScript } from 'next/document';

    class MyDocument extends Document {
      static async getInitialProps(ctx) {
        if (ctx?.pathname && !ctx?.pathname?.endsWith('_error')) {
          await revalidate().then((shouldUpdate) => {
            if (shouldUpdate) {
              console.log('Hot Module Replacement (HMR) activated', shouldUpdate);
            }
          });
        }

        const initialProps = await Document.getInitialProps(ctx);
        return initialProps;
      }

      render() {
        return (
          <Html>
            <Head />
            <body>
              <Main />
              <NextScript />
            </body>
          </Html>
        );
      }
    }
    ```
  </Tab>
  <Tab label="Stale While Revalidate">
    Aunque no se recomienda por el riesgo de errores de hidratación, este método consiste en escuchar el evento 'finish' del objeto de respuesta y después comprobar si hay actualizaciones. Puede ser útil en escenarios concretos en los que las actualizaciones pueden aplicarse con menos frecuencia o en los que la coherencia inmediata entre servidor y cliente no es tan crítica.

    **Cómo funciona:**

    - **Después de responder al cliente**, el servidor escucha el evento 'finish' del objeto de respuesta.
    - **Una vez enviada la respuesta**, comprueba si hay actualizaciones.
    - **Si encuentra actualizaciones**, las registra o actúa en consecuencia, aunque las actualizaciones solo se aplicarán a las solicitudes posteriores.

    **Ejemplo de implementación:**

   ```jsx title="_document"
    static async getInitialProps(ctx) {
      const initialProps = await Document.getInitialProps(ctx);
      ctx?.res?.on('finish', () => {
        revalidate().then((shouldUpdate) => {
          console.log('Response sent, checking for updates:', shouldUpdate);
        });
      });
      return initialProps;
    }
    ```
  </Tab>
</Tabs>

### Chunk flushing

El chunk flushing intenta "volcar" los chunks usados durante el SSR para que las etiquetas `<script>` puedan enviarse al navegador.

```jsx title="_document"
import Document, { Html, Head, Main, NextScript } from 'next/document';
import {
  revalidate,
  FlushedChunks,
  flushChunks,
} from '@module-federation/nextjs-mf/utils';

class MyDocument extends Document {
  static async getInitialProps(ctx) {
    if (ctx.pathname) {
      if (!ctx.pathname.endsWith('_error')) {
        await revalidate().then((shouldUpdate) => {
          if (shouldUpdate) {
            console.log('should HMR', shouldUpdate);
          }
        });
      }
    }

    const initialProps = await Document.getInitialProps(ctx);

    const chunks = await flushChunks();

    return {
      ...initialProps,
      chunks,
    };
  }

  render() {
    return (
      <Html>
        <Head>
          <FlushedChunks chunks={this.props.chunks} />
        </Head>
        <body>
          <Main />
          <NextScript />
        </body>
      </Html>
    );
  }
}
```
